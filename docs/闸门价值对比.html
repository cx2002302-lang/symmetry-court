实验设计（30 秒看懂）

每个案卷里的"被告群"＝真实工程里会有人提的合并主张。两种决策方式各跑一遍：

核心结果：朴素臂的 7 次放行里，1 次是静默破坏

8 案 26 群。朴素臂（只看结构）共放行 7 次合并——其中 6 次恰好安全（填充态对换，压缩 1.03–1.14×），1 次是陷阱：TCP 孪生对（FIN-WAIT-2 ↔ CLOSING）。闸门臂全部拦对放对，总耗时约 4 秒量级（26 群 8 案，单机实测求和，精确值见 json）。
一句话：闸门不是每次都救命——它救的正是"结构一样、事件不一样"这一类你用眼睛和结构工具都看不出的坑；其余时候它花几秒钟给你一张"压缩无害"的收据。

诚实声明（三条）：① 朴素臂是决策方式的代理（"结构像就合并"），不是某个具体第三方工具——但这正是 networkx 不带标签口径的同类做法，TCP 孪生案里它确实判"可换"；② "破坏格"按事件名钉死口径逐格对账计（合并后行为会改变的 (状态×事件) 数），协议类案卷奖励全零，判定全在转移层；③ 闸门放行群破坏格恒为 0 是判据的数学性质（pass 要求逐格 TV≤1e-9），不是本次运行的巧合。闸门耗时为单机量级记录，精确值在 comparison.*.json。

怎么复跑

compare 已是法庭正式子命令（纯标准库）：
# 法庭自有三案
python -X utf8 -m symmetry_court compare

# 任意同格式案卷集（例：实战盲测五案）
python -X utf8 -m symmetry_court compare --root <cases目录> --out <输出目录>
退出码 0 = 对比完成且「放行群零破坏、拒答群全部有据」一致性成立。逐案收据：verdicts/comparison.<case>.json；汇总：verdicts/comparison.summary.json。
