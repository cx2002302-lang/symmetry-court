核心结果：朴素臂的 25 次放行里，5 次合并会真改行为

12 案 45 群（compare v2：闸门臂按各群声明口径对账；2026-11-04 起兼容逐元素 action_maps，见下方"口径尊重"节；2026-11-04 加入 lightsout3 与 sliding2x3 案、2026-11-07 加入 hanoi3 案后刷新）。朴素臂（只看结构）共放行 25 次合并——其中 20 次恰好安全（9 次填充态对换，压缩 1.001–1.143×；11 次声明口径真对称：2048 案 g1/g3/g4、Lights Out 案 g1/g3/g4/g5、滑块案 sliding2x3 的 g1/g4 与汉诺塔案 hanoi3 的 g1/g3，声明口径下逐格零改），5 次是陷阱：TCP 孪生对（FIN-WAIT-2 ↔ CLOSING，6 格）、2048 案键钉死的 90° 旋转（740 格）、Lights Out 案键钉死的 90° 旋转（12288 格）、滑块案方向钉死的左右镜像（1440 格）与汉诺塔案柱对钉死的 A↔B 换柱（122 格）。2048 案的 3 个声明口径主张（g1/g3/g4）、Lights Out 案的 3 个 explicit 主张（g1/g4/g5）、滑块案的 2 个 explicit 主张（g1/g4）与汉诺塔案的 2 个 explicit 主张（g1/g3）闸门均放行——2048 案三群曾于 2026-11-03 因引擎 explicit 层的单映射局限被误拒，上游 2026-11-04 以逐元素 action_maps 修复后翻案兑现（下节详述）。闸门臂放行 20 次全部零破坏，总耗时约 8.8 秒（45 群 12 案，单机实测求和，精确值见 json）。
一句话：闸门不是每次都救命——它救的正是"结构一样、事件不一样"这一类你用眼睛和结构工具都看不出的坑；其余时候它花几秒钟给你一张"压缩无害"的收据。（它也曾误拒：mini2048 案 2026-11-03 当场抓到引擎 explicit 层的单映射局限，误拒全程公开记录；上游 2026-11-04 修复后 g1/g3/g4 翻案兑现，见下节——错判史同样保留，不删。）

怎么复跑

compare 已是法庭正式子命令（纯标准库；v2 起按群声明分派口径：explicit 群原样跑、fixed/无声明群 --strict）：
# 法庭自有十二案（含 mini2048/lightsout3/sliding2x3/hanoi3 与收编五案）
python -X utf8 -m symmetry_court compare

# 任意同格式案卷集（例：实战盲测五案的原始目录）
python -X utf8 -m symmetry_court compare --root <cases目录> --out <输出目录>
退出码 0 = 对比完成且「放行群零破坏、拒答群全部有据」一致性成立。逐案收据：verdicts/comparison.<case>.json；汇总：verdicts/comparison.summary.json。

2048 正控案：从击穿单映射局限到翻案兑现（2026-11-03 发现 → 2026-11-04 修复）

翻案兑现（2026-11-04，上游 wuxing-gua 逐元素 action_maps 修复落地本仓 vendored 引擎）：群文件 explicit 声明现支持 action_maps——与 elements 一一对应的逐元素动作映射，装载时校验同态律 ρ(g∘h)=ρ(g)∘ρ(h)（≤500 元素全检有序对，本仓六群全为 homomorphism_checked=full）；旧单 action_map 行为不变、标 deprecated。g1/g3/g4 按声明口径翻案放行（实跑收据 cases/mini2048/receipts/，引擎不带 --strict）：g1 order 4、70 轨道（压缩 3.657×）、g3 order 2、136 轨道（1.882×）、g4 全 D4 order 8、55 轨道（4.655×），worst_tv 全 0；g2（键钉死）/g5（假群）维持拒答、g6 维持放行，恒等元对照实验（单恒等映射 → 仍拒于 rot90 元素）照旧成立——legacy 行为不变的直接证据。compare 台账随之更新：闸门放行 7 → 10（放行群破坏格恒 0），朴素臂有害放行 5 → 2（"被救下的合并"从 5 降回真陷阱 2：g1/g3/g4 此前计入"被救"实为引擎误拒，修复后归位为正常放行），朴素臂真破坏格 2486 → 746。一致性 PASS。
为什么 2048 的 D4 是真对称：棋盘转 90° 后按"改了名的方向键"玩，游戏一毫不差——状态置换 π 与方向键改名 ρ(π) 一一配对，π ↦ ρ(π) 满足群同态律。8 个 (π, ρ(π)) 配对由案卷生成器在 24 个动作双射中穷举推导并机器断言（唯一性 + 同态律，每次 make --check 重验）；群文件现按逐元素映射完整声明这 8 张表，引擎装载时独立重验同态律。这是 explicit 口径的第一个真实系统样本，也是"放行方向"的第一个非平凡真对称案卷。
翻案史（2026-11-03 记录，原文保留——诚实传统，不删）：当时 vendored 判官的 explicit 层把一个声明的 action_map 用于闭包群每一个元素——含恒等元。恒等元在 ρ≠id 时必挂（dist(s,a) = dist(s, ρ(a)) 对所有 s,a 成立强制 ρ = 恒等），而闭包必含恒等元，所以任何非平凡"动作改名"对称在工具层结构性不可能放行。当时实测指纹（收据 cases/mini2048/receipts/ 的 2026-11-03 版，引擎不带 --strict）：g1 拒于恒等元（3/4 元素不过，唯一通过者恰是 rot90 本身）、g3 拒于恒等元（1/2）、g4 拒于恒等元（7/8）；恒等元对照实验双向互证——同一群文件把声明映射换成恒等后 first_bad 变为 rot90，排除"映射选错了"。同模型 g6_pads 照常放行（排除模型坏损），g2（键钉死，740 格）/g5（假群）照常拒答。g3 的声明口径逐格对账 = 0 破坏仍被拒，是那条局限最干净的单点证据。当时的翻案钩子写明："修复归上游 wuxing-gua（逐元素 action_maps，或由生成元映射按同态律推导并验证）；修复后 g1/g3/g4 预期翻案放行——g4 全 D4 压缩读数 4.655×（55 轨道）、g1 3.657×、g3 1.882×——g2/g5 维持拒答、g6 维持放行。"——本节第一段的实跑读数与之逐项相符，钩子兑现。
compare v2 的口径尊重（2026-11-04 更新）：旧版闸门臂无条件 --strict，对 explicit 声明群是错误覆盖。v2 起按群声明分派：声明 explicit → 不加 --strict 原样跑，损害台账按声明口径改名事件后对账（上表带 * 行）；声明 fixed 或无声明 → 维持 --strict。2026-11-04 起声明口径含逐元素映射（对账按每元素各自的 ρ）。声明口径下放行 = 逐格零误差，放行群破坏格 0 依旧是判据性质。

Lights Out 正控案 lightsout3：第二个非平凡真对称正控（2026-11-04 入卷）

与 mini2048 同群、不同机理：同为 8 元素棋盘群 D4、同样逐元素按钮映射 explicit 放行，但机理不同——2048 的对称活在"滑动 + 合并"的方向规则里，Lights Out 的对称活在 Toggle 代数里（按键 = 异或翻转自身与正交相邻灯，Wikipedia："Pressing any of the lights will toggle it and the four adjacent lights."）。案卷五群：g1 旋转 C4（explicit）放行，140 轨道（3.657×）；g2 同一旋转按钮钉死（fixed）拒答，键钉死口径下 12288 个行为格被改写（512 态 × 9 按钮中 3 个旋转元素各破 4096 格）——朴素臂看不见这道坎，闸门拦下；g3 全盘取反（fixed）放行，256 轨道（2.000×）；g4 全 D4（explicit，主正控）放行，102 轨道（5.020×）；g5 直积 D4×C2 16 阶（explicit）放行，51 轨道（10.039×）——全盘取反与 D4 每个元素可交换（生成器逐元素断言），几何对称与 Toggle 代数对称相互独立。512 态全部为真态：3×3 翻转矩阵在 GF(2) 上秩 9，本案没有填充态，平凡正控因此换机理（全盘取反，非填充对换；案卷工程裁决 2026-11-04：忠实转录优先于凑正控形式，偏离如实记录在案卷 README 与 model.json）。收据：cases/lightsout3/receipts/（引擎声明口径 live 跑）+ verdicts/lightsout3.verdict.json（三方庭审）+ verdicts/comparison.lightsout3.json（本页读数）。

滑块正控案 sliding2x3：第三个非平凡真对称正控（2026-11-04 入卷）

第三种群结构、pads 正控回归：2×3 棋盘是非正方形矩形，完整几何对称群是 4 阶 Klein 四元群 V4 = C2 × C2（恒等 / 左右镜像 / 上下镜像 / 180° 旋转）——不存在 90° 旋转，生成器穷举 720 个格子双射对邻接图逐一机器验证"恰 4 个幸存"，案卷因此集齐三种被放行的群结构：D4（mini2048、lightsout3）、D4×C2（lightsout3 g5）、V4（本案）。机理是邻接：一条规则——一块滑一格进相邻空位（Wikipedia "15 puzzle"："Tiles in the same row or column of the open position can be moved by sliding them horizontally or vertically, respectively."），棋盘镜像自带被迫的方向改名（hflip：left↔right；vflip：up↔down；rot180：两者都换）。案卷四群：g1 左右镜像 C2（explicit）放行，664 轨道（1.542×）；g2 同一镜像方向钉死（fixed）拒答，钉死口径下 1440 个行为格被改写——朴素臂看不见这道坎，闸门拦下；g3 填充态对换（fixed）放行，1023 轨道（1.001×）——pads 正控回归：本案 1024 态中 720 个真排列 + 304 个真实填充态（未用编码秩），lightsout3 无填充态案之后平凡正控恢复 pads 形态（定位如实记录：mini2048 本就配对 explicit 与真实填充态及 pads 正控，本案在 V4 结构上再次配对）；g4 全 V4（explicit，主正控）放行，484 轨道（2.116×）——Burnside 交叉验证 (720+0+0+0)/4 = 180 个真态轨道 + 304 个填充单点。Johnson & Story 奇偶分裂（一半起始局面无解）记录不修复：两类都是真态，BFS 实测恰达 360。收据：cases/sliding2x3/receipts/（引擎声明口径 live 跑）+ verdicts/sliding2x3.verdict.json（三方庭审）+ verdicts/comparison.sliding2x3.json（本页读数）。

汉诺塔正控案 hanoi3：第四个非平凡真对称正控（2026-11-07 入卷）

第四种群结构、首个『动作 = 有序对』语义、pads 正控继续：汉诺塔的柱名除恒等外别无内容，三根柱的任何重标都精确保持移动机制——完整柱重标群是 S3（6 阶：恒等 / 3 个对换 / 2 个轮换），生成器动态机器验证：6 个柱置换的每一个都恰有一个被迫的有序对改名（穷举全部 6! = 720 个动作排列），六个 (π, ρ(π)) 配对在全部 36 个有序对上满足同态律；两个非柱重标的假状态映射（盘对换、盘轮换）任何改名都不成立。这是本案卷第四个被放行的群结构（D4、D4×C2、V4 之后），且是第一个非交换群。动作语义是首次出现的有序柱对 (X, Y) = "取 X 柱顶盘放到 Y 柱"（Wikipedia "Tower of Hanoi"："Each move consists of taking the upper disk from one of the stacks and placing it on top of another stack or on an empty rod."），柱重标把动作按有序对一起改名 (X, Y) ↦ (πX, πY)——源文自己写明这一对称（"the problem is symmetric for permutations of the names of the pegs (symmetric group S3)"）。案卷四群：g1 A↔B 换柱 C2（explicit）放行，19 轨道（1.684×）——Burnside：(27+1)/2 = 14 个真态轨道（A↔B 只固定全盘在未换柱 C 上的那个态）+ 5 个填充单点；g2 同一换柱柱对钉死（fixed）拒答，钉死口径下 122 个行为格被改写——朴素臂看不见这道坎，闸门拦下（本案卷第 5 个有害朴素放行）；g4 填充态对换（fixed）放行，31 轨道（1.032×）——pads 正控继续：本案 32 态中 27 个真排列 + 5 个真实填充态（未用三进制秩），mini2048 g6、sliding2x3 g3 之后 pads 形态保持；g3 全 S3（explicit，主正控）放行，10 轨道（3.200×）——Burnside：(27+3)/6 = 5 个真态轨道（大小 3,6,6,6,6）+ 5 个填充单点。源文算术全程机器断言：每真态恰 3 个合法有序对（三个角态恰 2 个，"every node has three edges to other nodes, except the three corner nodes, which have two"）；BFS 自目标可达全部 27 真态；起点到目标恰 7 = 2³ − 1 步（"With three disks, the puzzle can be solved in seven moves"）。奖励全零属设计（谜题无计分），完成条件（整叠到 C 柱）记录在 meta.win_condition。relabel 列读法：6 动作 > 5 位，盖章 relabel 框架解析为 generalized 判官，从状态置换自身推导动作改名——与被迫的逐元素有序对映射重合，该列与 explicit 收据同判放行（对比 mini2048/sliding2x3 的位串诊断列拒答）。32 态在规模护栏内，陪审团自同构枚举实跑：720 个结构自同构（6 真态 S3 重标 × 5! 填充排列）对 120 个带标签自同构（5! 填充排列 × 真态恒等）——独立机器验证"带标签真态空间的自同构群恰为 S3"。收据：cases/hanoi3/receipts/（引擎声明口径 live 跑）+ verdicts/hanoi3.verdict.json（三方庭审）+ verdicts/comparison.hanoi3.json（本页读数）。
